# 바이브코딩 작업지시서 — 코드 변경 대기 목록

작성일 2026-08-27 · 각 작업(T1~T5)은 독립적으로 LLM에 붙여넣어 진행할 수 있게
배경·지시·금지·완료 판정을 자체 포함한다. **T1 → T2 순서만 지키면 나머지는 순서 무관.**

## 공통 컨텍스트 (모든 작업 프롬프트 앞에 붙일 것)

> Django 5.x 기반 지역별 분리배출 RAG 챗봇(Ecobot). 지역 정의의 단일 원본은
> `members/regions.py` 의 `REGIONS` 리스트이며, `REGION_CHOICES`·별칭 매칭·가이드
> 슬러그가 전부 여기서 파생된다. 지역 코드를 쓰는 모델 필드는 4개 앱 5개
> (`members.Member.region`, `chat.ChatSession.region`, `chat.ChatLog.region`,
> `boards.Board.region`, `rag.Document.region`).
>
> 절대 규칙:
> 1. 마이그레이션 파일은 반드시 커밋에 포함한다. makemigrations 는 한 사람만 돌린다.
> 2. 데이터 커밋과 코드 커밋을 분리한다.
> 3. 작업 후 검증 3종을 돌린다: `python verify_regions.py` ·
>    `python check_guide_format.py data/guide` · `python evals/run_eval_hybrid.py`
> 4. `REGIONS` 리스트에 항목을 넣을 때는 닫는 대괄호 `]` 바로 앞에 추가하고,
>    그 아래의 `COMMON_CODE`/`COMMON_LABEL` 정의와 파생물 블록은 건드리지 않는다.

## T1. 지역 choices 를 콜러블로 전환 — 이후 지역 추가 시 마이그레이션 0개

상태: **사전 검증 완료** (2026-08-26, Django 5.2 + sqlite 로 이 리포 스냅샷에서 실험).

배경: Django 5.0+ 는 모델 필드 `choices` 에 콜러블을 받고, 마이그레이션에는 함수
참조만 기록한다. 실험 결과 전환 시 마지막 마이그레이션 4개가 생기고, 이후
`REGIONS` 에 지역을 추가해도 `makemigrations` 가 "No changes detected" 를 낸다.

지시:
1. `members/regions.py` 맨 아래에 추가:
   ```python
   def region_choices() -> list[tuple[str, str]]:
       """모델 필드 choices 용 콜러블. Django 5.0+ 는 choices 에 콜러블을 받으며,
       마이그레이션에는 이 함수의 참조만 기록되므로 REGIONS 를 고쳐도
       새 마이그레이션이 생기지 않습니다."""
       return [(COMMON_CODE, COMMON_LABEL)] + [(r["code"], r["label"]) for r in REGIONS]
   ```
2. 다섯 필드의 `choices=REGION_CHOICES` 를 `choices=region_choices` 로 교체.
   임포트는 `from members.regions import region_choices` (members 앱 내부에서는
   `from .regions import ...`). 기존 `REGION_CHOICES` 임포트는 다른 코드가 쓰므로
   지우지 않는다.
3. `python manage.py makemigrations members chat boards rag` → 파일 4개 생성 확인 후 커밋.

금지: `REGION_CHOICES` 리스트 자체를 없애지 말 것 (views·forms 가 순회함).
DB 스키마를 바꾸는 어떤 변경도 하지 말 것.

완료 판정:
- 생성된 마이그레이션 안에 `choices=members.regions.region_choices` (참조)가 있다.
- `REGIONS` 에 임시 항목을 넣고 `makemigrations --dry-run` → **"No changes detected"**.
  확인 후 임시 항목 제거.
- `python verify_regions.py` 통과, 회원가입 드롭다운에 지역이 정상 표시.

## T2. measure_threshold 의 지역 목록 잔재 정리 — 통합에서 누락된 버그

배경: `rag/management/commands/measure_threshold.py` 39행이 지역 6개를 아직
하드코딩하고 있다 (`["seoul", "cheonan", "busan_namgu", "sejong",
"incheon_michuhol", "jeju"]`). regions.py 통합 때 빠졌고, 대전·울산·수원도 없다.
이대로면 임계값 측정이 신규 지역을 건너뛴다.

지시: 39행을 `from members.regions import REGION_CODES` 재사용으로 교체.
`REGION_CODES` 는 regions.py 에 이미 있는 튜플이며 common 을 포함하지 않는다
(이 커맨드의 의도와 일치).

완료 판정: `python manage.py measure_threshold` 실행 시 등록된 모든 지역
(현재 9개)을 순회하며 표를 출력한다.

## T3. `data/incoming/` 스테이징 폴더 도입

배경: 수집 파일을 색인에 잡히지 않게 비축하기 위한 폴더. `rag_reindex`(files
모드)와 `seed_docs`(db 모드)는 `settings` 의 `LAWS_DIR`·`GUIDE_DIR`·`DOCS_DIR`
세 폴더만 비재귀로 읽으므로, `data/incoming/` 은 만들기만 하면 색인에서 제외된다.

지시:
1. `data/incoming/` 생성, 안에 `README.md` 로 용도 두 줄 설명
   (수집 비축용 · 색인 안 됨 · 반영 시 `data/guide/` 로 이동).
2. 빈 폴더가 git 에 남도록 README 를 커밋.

금지: **`config/settings.py` 의 `GUIDE_DIR`/`DOCS_DIR`/`LAWS_DIR` 나
`_load_from_files()`/`seed_docs` 의 폴더 목록에 incoming 을 추가하지 말 것.**
색인에서 빠지는 것이 이 폴더의 존재 이유다.

완료 판정: incoming 에 txt 를 하나 둔 상태로 `python manage.py rag_reindex`
실행 → 적재 로그에 그 파일이 나타나지 않는다.
`python check_guide_format.py data/incoming` 은 정상 동작한다.

## T4. 신규 지역 배치 반영 절차 (대구 예시)

전제: T1 완료 상태면 마이그레이션이 생기지 않는다. 미완료면 이 작업이
`AlterField` 마이그레이션 4개를 만들며, 반드시 커밋에 포함한다.

지시 (배치에 포함된 지역마다 반복):
1. `members/regions.py` 의 `REGIONS` 닫는 대괄호 앞에 항목 추가:
   ```python
   {
       "code": "daegu",
       "color": "#4A7C2D",
       "label": "대구",
       "slug": "daegu",
       "aliases": ["대구광역시", "대구시", "대구"],
   },
   ```
2. 수집 파일 이동: `data/incoming/[가이드]_대구시_분리배출_요령.txt` →
   `data/guide/`. 파일명과 첫 줄 제목 양쪽에 지역 키워드("대구")가 있는지 확인.
3. 평가셋(`evals/qa_set.json`):
   - `q027`(대구 수성구 = 자료 없음)은 대구 반영과 동시에 **다른 미보유 지역
     문항으로 교체**한다 (권장: 강원 춘천 — 수집전략 문서에서 '문항 예약'으로
     지정됨). `region` 필드는 보유 지역 중 하나로 두는 기존 방식 유지.
   - 대구 `region_specific` 2문항 추가. **데이터 수집자가 아닌 사람이 출제.**
4. `members/guides.py` 의 `region-daegu` 콘텐츠는 지연 가능 — 없으면 랜딩
   카드에 안 나올 뿐, 챗봇·드롭다운은 동작한다 (HomeView 가 필터링).
5. T1 미완료 시에만: `makemigrations members chat boards rag` → 4개 커밋.

완료 판정 (게이트):
- `python check_guide_format.py data/guide` 오류 0건
- `python manage.py seed_docs --reindex` 적재 로그에 `(지역: daegu)` 확인
- `python verify_regions.py` — 기존 지역 태깅 동일 + 별칭 충돌 0건
- `python evals/run_eval_hybrid.py` — **기존 지역 점수가 배치 전과 같거나 높다.**
  떨어지면 이 배치의 지역을 절반씩 빼며 이분탐색.

## T5. RUN.md C절 갱신

배경·수정안 전문이 `docs/RUN.md_수정안.md` 에 이미 있다.

지시: 그 문서의 "수정안" 블록대로 RUN.md C절 두 줄을 교체하고,
"evals(RAGAS)" 명칭을 "evals(LLM 혼합 평가)" 로 바꾸고, 재색인 명령이
`RAG_SOURCE` 모드에 따라 다르다는 안내 인용구를 C절 표 아래에 추가한다.
A절 끝의 청크 수는 재색인 후 실측값으로 갱신 (문서 수 24개는 유지).

완료 판정: RUN.md 와 HANDOFF.md 의 상태 서술이 모순되지 않는다.
