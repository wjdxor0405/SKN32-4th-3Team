# 지역 확장 2단계 실행 계획

작성일 2026-08-25 · 대상 `data/guide/` + 지역 코드 관련 코드

---

## 전체 순서

```
[1단계] 기존 6개 심화          ← 데이터만. 코드 변경 0건
   ↓
[게이트] 기준선 측정            ← 이 숫자가 2단계 회귀 판정 기준이 됨
   ↓
[선행]  REGION_MAP 통합         ← 코드 담당 작업. 이거 없이 광역 추가하면 오태깅
   ↓
[2단계] 광역 추가              ← 지역 1개당 파일 5곳 + 마이그레이션 + 평가셋
```

1단계와 2단계 사이를 붙이지 않는 이유: 데이터 추가 효과와 코드 변경 부작용이
섞이면, 점수가 떨어졌을 때 원인을 가릴 수 없다.

---

## 게이트 — 1단계 종료 조건

2단계로 넘어가기 전에 아래 세 숫자를 기록해 둔다.

```bash
python check_guide_format.py data/guide      # 오류 0건
python manage.py seed_docs --reindex
python evals/run_eval_hybrid.py
```

| 지표 | 기록할 것 |
|---|---|
| `region_specific` 10문항 | 지역별 점수 (before / after) |
| `no_answer` 거부율 | 지역 정보가 늘면서 억지 답변이 늘지 않았는지 |
| 전체 정답률 | 공통 문서가 밀려나지 않았는지 |

특히 **`no_answer` 거부율**을 봐야 한다. 지역 문서를 채우면 모델이 "뭐라도
답할 근거"를 얻어 자료 없는 질문에도 답을 지어내기 쉬워진다. 이 값이
떨어졌다면 지역 파일에 추측성 서술이 들어갔다는 신호다.

## 선행 작업 — REGION_MAP 통합 (코드 담당)

지금 지역 코드 매핑이 **세 벌**이고 내용이 서로 다르다.

| 위치 | 기준 | 특이 키 |
|---|---|---|
| `seed_docs.REGION_MAP` | 문서 **제목** | `"부산 남구"`, `"인천 미추홀구"` (띄어쓰기 포함) |
| `rag/service.py::_extract_region` | **파일명** | **`"부산"`** ← 문제 |
| `members/guides.py` + `templates/home.html` | 자체 명명 | `region-busan`, `region-incheon` |

### 왜 먼저 고쳐야 하나

부분 문자열 매칭이라 **상위 지역명이 하위 지역을 먹는다.**

| 새 문서 | seed_docs | files 모드 | |
|---|---|---|---|
| `[부산 해운대구]` | `None` (공통) | `busan_namgu` | 불일치 · 남구 문서로 오태깅 |
| `[서울 강남구]` | `seoul` | `seoul` | 둘 다 오태깅 |

에러도 경고도 없이 조용히 틀린다. 대전·울산처럼 충돌 없는 광역만 넣는다면
당장은 터지지 않지만, 부산·인천을 광역으로 확장하는 순간 바로 발생한다.

### 통합 스펙

- 단일 정의를 한 곳에 둔다 (예: `members/regions.py`).
  `REGION_CHOICES`, 제목/파일명 키워드, `guides.py` 키를 모두 여기서 파생.
- **긴 키부터 매칭**한다 (`sorted(keys, key=len, reverse=True)`).
  삽입 순서에 의존하지 않게 만드는 것이 핵심.
- `rag/service.py` 의 `"부산"` 키를 **삭제**한다.
- `guides.py` 키를 `REGION_CHOICES` 코드와 일치시킨다
  (`region-busan` → `region-busan_namgu`, `region-incheon` → `region-incheon_michuhol`).
- 회귀 확인: 통합 전후로 기존 15개 파일의 태깅 결과가 **동일**해야 한다.

## 광역 후보 고르는 기준

### ① 단일 체계가 성립하는가 (가장 중요)

광역시는 배출 요일·시간·수수료를 **자치구 조례**로 정하는 경우가 많아
"시 전체 하나의 답"이 없는 항목이 생긴다. 서울이 이미 그렇다.

성립하지 않으면 서울 초안에서 쓴 방식을 그대로 쓴다 —
없는 답을 지어내지 말고 *"자치구마다 다르며 확인 경로는 ○○"* 로 서술한다.
챗봇 답변으로도 그게 정확하다.

광역도(경기·강원 등)는 시·군 단위로 더 잘게 갈리므로 **비권장**.

### ② 이름 충돌이 없는가

| 후보 | 판정 | 이유 |
|---|---|---|
| 대전 | 안전 | 기존 키와 겹치지 않음 |
| 울산 | 안전 | 기존 키와 겹치지 않음 |
| 대구 | **주의** | 평가셋 `q027` 이 "대구 수성구 = 자료 없음"을 정답으로 쓴다 |
| 광주 | **주의** | 광주광역시 ↔ 경기도 광주시. 부분 문자열이 동일 |
| 부산·인천 | **주의** | 기존 기초단체와 계층 충돌. 선행 작업 필수 |

### ③ 자료 접근성 — 시 차원 통합 안내 페이지가 있는지 먼저 확인
### ④ 팀 연고 — 시연 때 실제로 확인해 줄 사람이 있는 지역이면 가산점

**권고: 대전 → 울산 순으로 1개씩.** 한 번에 여러 개 넣으면 회귀 원인 추적이 어렵다.

## 2단계 체크리스트 (지역 1개당)

### 코드

| 파일 | 변경 |
|---|---|
| `members/models.py::REGION_CHOICES` | `("daejeon", "대전")` 추가 |
| 통합된 REGION_MAP | 제목·파일명 키워드 `"대전"` 추가 |
| `members/guides.py::GUIDE_DATA` | `'region-daejeon'` 항목 추가 |
| `templates/home.html` (64~87행) | 지역 카드 추가 (하드코딩 구간) |
| `rag/management/commands/measure_threshold.py::REGIONS` | 코드 추가 |

드롭다운(회원가입·프로필·게시판·채팅·문서업로드)은 `REGION_CHOICES` 를
순회하므로 자동으로 따라온다. 손댈 필요 없다.

### 마이그레이션

`REGION_CHOICES` 를 공유하는 필드가 **4개 앱 5개**다.

- `members.Member.region`
- `chat.ChatSession.region`
- `chat.ChatLog.region`
- `boards.Board.region`
- `rag.Document.region`

```bash
python manage.py makemigrations members chat boards rag
python manage.py migrate
```

스키마는 안 바뀌지만 Django 는 `AlterField` 를 5개 만든다.
(모델은 `Member` · `ChatSession` · `ChatLog` · `Board` · `Document` 다.
 마이그레이션 **파일**은 앱 단위라 4개 생긴다 — chat 만 필드가 둘이다.)
앱을 빠뜨리면 팀원마다 마이그레이션 상태가 갈린다. **커밋에 반드시 포함.**

### 데이터

- 파일명: `[가이드]_대전시_분리배출_요령.txt`
- 첫 줄 제목: `[대전광역시] 분리배출 가이드 및 재활용품목 배출 요령`
- **제목과 파일명 양쪽에 매칭 키워드(`대전`)가 들어가야 한다.**
  적재 모드에 따라 보는 곳이 다르다.
- 섹션 구성은 1단계에서 확정한 것과 동일하게:
  배출 요일·시간 / 품목별 요령 / 음식물 / 대형폐기물 / 유해폐기물 / 문의

### 검증

```bash
python check_guide_format.py data/guide
python manage.py seed_docs --reindex     # 적재 로그에서 region 값 육안 확인
python manage.py measure_threshold       # 지역이 늘면 임계값 재측정
python evals/run_eval_hybrid.py          # 기존 6개 지역 점수 회귀 확인
```

**기존 6개 지역 점수가 떨어졌는지**가 핵심 확인 항목이다. 청크가 늘면서
지역명이 비슷한 문서끼리 서로를 밀어낼 수 있다.

## 평가셋 관리 규칙

`run_eval_hybrid.py` 는 `no_answer` 문항을 별도로 모아 **거부율**을 낸다.
문항이 하나도 없으면 이 지표는 `None` 이 되어 사라진다.

- 지역형 `no_answer` 는 `q027`(대구 수성구) **하나뿐**이다.
  대구를 추가한다면 삭제하지 말고 **다른 미보유 지역으로 교체**한다
  (예: 강원 춘천). 지표를 잃지 않는 것이 목적이다.
- 교체 시 `region` 필드는 **보유 지역 중 하나**로 둔다.
  `q027` 이 `busan_namgu` 로 되어 있는 것과 같은 방식이다 —
  "부산 사용자가 대구를 물었을 때" 상황을 재현하기 위함.
- 새 지역마다 `region_specific` **2문항씩 추가**한다.
  기존 지역이 2~4문항씩이므로 균형을 맞춘다.
- 문항 추가는 데이터 작성자가 아니라 **다른 사람이** 하는 편이 좋다.
  자기가 쓴 문서를 보고 문제를 내면 평가가 아니라 자문자답이 된다.

## 롤백

- **데이터만 되돌리기**: `seed_docs` 는 폴더 기준 동기화라
  파일을 지우고 재실행하면 레코드도 삭제된다 (`_remove_stale`).
- **코드 변경**: 마이그레이션이 끼므로 별도 브랜치에서 작업하고,
  게이트 측정값이 회귀하면 브랜치째 되돌린다.
