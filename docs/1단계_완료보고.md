## 중간에 한 번 되돌아간 일 — 청크 밀림

처음 병합본은 hash 백엔드 측정에서 **점수가 떨어졌습니다** (86.7% → 80.0%,
`region_specific` 10/10 → 8/10). 원인은 지역 문서에 배정되는 검색 자리가
2청크뿐인데 청크 수만 늘린 것이었습니다.

- 제주 10 → 15청크, 미추홀 10 → 12청크로 늘면서 **정답 청크가 2위 밖으로 밀림**
- 특히 미추홀에 쓴 `- 배출 요일·시간은 앞 섹션 참조` 가 치명적이었습니다.
  "재활용품"과 "배출 요일"을 한 청크에 담았는데 **정답은 없는** 문장이라,
  검색어와 표면이 겹쳐 정답 청크를 이겼습니다

**RAG 에서 상호참조는 통하지 않습니다. 청크는 서로를 보지 못합니다.**
중복을 피하려고 "앞 섹션 참조"라고 쓴 것이 정확히 역효과였습니다.

### 적용한 처방 3가지

1. **미끼 문장 제거** — 순수 포인터 문장 삭제 (전수 조사 결과 1곳)
2. **정답 청크 라벨에 검색어 심기** — 청킹이 라벨을 `[섹션 > 품목]` 형태로
   청크 맨 앞에 붙이는 점을 이용
   - 미추홀 `[배출 요일 …]` → `[재활용품 배출 요일 …]`
   - 제주 `[RFID 개별계량 배출]` → `[음식물쓰레기 배출 방법 (RFID 개별계량)]`
3. **블록 병합** — 서울 27 → 24청크, 제주·미추홀은 중복 블록 삭제로 상쇄

처방 후 openai 측정에서 두 문항 모두 **5/5 로 회복**되었습니다.
점수가 오른 부산 남구·천안은 손대지 않았습니다.

## 적용 방법 (2026-08-26 실행 완료)

> 아래 절차는 이미 수행했습니다. 재현이 필요할 때 참고용으로 남깁니다.

### 1단계 — 파일 교체 (전원 공통)

```bat
copy guide_merged\*.txt data\guide\
python check_guide_format.py data\guide
```

오류 0건을 확인하고 넘어갑니다.

### 2단계 — 재색인 (본인 `.env` 의 `RAG_SOURCE` 에 따라 하나만)

| `RAG_SOURCE` | 명령 |
|---|---|
| `files` (퀵스타트 구성) | `python manage.py rag_reindex` |
| `db` (실사용 구성) | `python manage.py seed_docs --reindex` |

`files` 모드는 `data/` 폴더를 직접 읽으므로 `seed_docs` 를 돌려도 색인에 반영되지 않습니다.
**본인 `.env` 를 먼저 확인하십시오.**

### 3단계 — 게이트 측정 (담당자 1명만)

```bat
python manage.py measure_threshold
python -m evals.run_eval_hybrid
python -m evals.run_report
```

기록할 세 숫자: `region_specific` 10문항 점수, `no_answer` 거부율, 전체 정답률.
**`no_answer` 거부율이 떨어졌다면 추측성 서술이 들어갔다는 신호입니다.**

### 게이트 측정 조건 — 반드시 지켜야 합니다

**`EMBEDDING_BACKEND=openai` + `RAG_SOURCE=db` 구성에서, 한 사람이 전담해 측정합니다.**

RUN.md 에 기록된 실측에 따르면 hash 임베딩 모드에서는 자료없음 판정이 사실상 무력합니다.
880청크 코퍼스에서 무관한 질의도 2-gram 우연 일치와 해시 충돌로 임계값(0.05)을 넘어
근거가 잡힙니다. **hash 모드로 재면 `no_answer` 거부율이 의미 없는 숫자로 나옵니다.**
`run_eval_hybrid` 는 채점에도 OpenAI 를 호출하므로 어차피 키가 필요합니다.

여러 명이 각자 환경에서 재고 숫자를 비교하면 어긋납니다. 측정자와 구성을 기록해 두십시오.

**실제로 겪은 함정 두 가지**

1. **hash 로 잰 숫자와 openai 숫자는 비교 불가.** hash 측정에서 80.0% 였던 것이
   openai 에서 90.0% 로 나왔습니다. 백엔드가 다르면 유사도 분포 자체가 다릅니다.
   hash 에서 튜닝한 처방을 실서비스 성능이라고 보면 안 됩니다.
2. **MySQL 로 전환하면 `migrate` 부터.** `rag_reindex` 가
   `Table 'ecora.documents' doesn't exist` 로 실패합니다. MySQL 은 빈 DB 라
   `migrate` → `createsuperuser` → `seed_docs --reindex` 순서가 필요하고,
   sqlite 의 계정·문서·대화 기록은 넘어오지 않습니다.

## 팀 확인이 필요한 사항 4가지

### 1. 천안 배출 요일 — 앱과 챗봇이 어긋날 수 있음
`members/guides.py`의 가이드 페이지에는 천안 단독주택이
"월·수·금(재활용), 화·목·토(일반)"으로 적혀 있으나,
천안시청 공식 자료에서 이를 뒷받침하는 근거를 찾지 못했습니다.
가이드 페이지 내용의 출처를 확인하거나, 시청에 직접 문의해 주세요.
**시연 중에 앱 화면과 챗봇 답변이 다르면 바로 드러납니다.**

### 2. 미추홀 재활용품 요일 — 조례와 구청 안내가 불일치
- 구청·언론: 2022년 5월부터 주 3회 (동별로 월·수·금 / 일·화·목)
- 조례 시행규칙: 매주 화·목요일 19:00~24:00

조례가 개정되지 않았거나 참조한 조례본이 옛것일 수 있습니다.
평가 문항 q020 "미추홀구 재활용품 배출 요일"은 구청 안내 기준으로 작성해
2026-08-26 측정에서 5/5 로 통과했습니다. **다만 조례가 근거라면 정답이 바뀝니다.**
2순위 조례 수집 때 우선 확인 대상입니다.

### 3. robots.txt 차단 — 교차 확인 필요
부산 남구청, 세종시, 천안시 누리집이 자동 접근을 막고 있어
**검색 결과 요약으로만 확인한 항목이 있습니다.**
팀에서 실제 페이지를 열어 아래 항목을 한 번 대조해 주세요.
- 부산 남구: 소형폐가전 수요일 무상수거, 폐의약품 수거함 위치
- 세종: 종이팩 별도회수처, 자원순환 이응봇 운영 방식
- 천안: 폐가전 수거일자(동남구 월·수·금 / 서북구 화·목·토)

### 4. 서울은 평가 문항이 0개
`region_specific` 10문항 중 서울 문항이 없습니다.
서울이 기본값 지역(`REGION_CHOICES` default="seoul")이라
실사용자와 심사자가 가장 많이 밟을 경로인데 평가에서 빠져 있습니다.
**문항 2개 추가를 권합니다.** 단, 데이터를 작성한 사람이 아닌 다른 팀원이 출제해야 합니다.

2026-08-26 측정에서 서울이 14/17 (82.3%) 로 유일하게 100% 가 아니었는데,
이는 서울 지역 문서의 문제가 아니라 **지역 무관 문항의 기본값이 서울로 잡히기 때문**입니다.
실패 3건 모두 공통 문서에서 답을 찾지 못한 사례이지 서울 가이드와는 무관합니다.
지역별 성적표를 읽을 때 이 점을 감안해야 합니다.

## 남은 실패 3건 — 데이터가 아니라 임계값 문제

세 문항 모두 **코퍼스에 답이 있습니다.** 그런데 답변이
`관련 문서를 찾을 수 없습니다` 였습니다. `RAG_MIN_SCORE=0.3` 을 넘긴 청크가
하나도 없었다는 뜻입니다.

| 문항 | 답이 있는 위치 |
|---|---|
| q005 뽁뽁이(에어캡) | 환경부 공통 기준 `[비닐류]` — "과자·커피 비닐, 양파망, 뽁뽁이, 택배봉투" |
| q012 소파 | 공통 대형폐기물 절차 — "장롱, 책상, 소파, 침대 프레임 등: 대형폐기물 신고 대상" |
| q025 텀블러 혜택 | 공통 탄소중립 제도 — 탄소중립포인트 적립 항목, "카페 텀블러 할인과 중복 가능" |

셋 다 **공통 문서**에 있고, 공통 몫은 1청크뿐이라 경쟁이 빡빡합니다.

### 지금 설정은 의도적으로 보수적입니다

**환각 0건 / 오거부 3건.** 확실하지 않으면 입을 다무는 성향이고,
그 대가로 답할 수 있는 것 3개를 놓쳤습니다. 시연에서 틀린 답을 자신 있게
말하는 것보다는 낫지만, "뽁뽁이 어디 버려요?" 같은 평범한 질문에
모른다고 하면 인상이 나쁩니다.

### 두 가지 선택지

**A. 임계값을 내린다** — `python manage.py measure_threshold` 로 실측 후 판단.
내리면 `no_answer` 3문항(대구 수성구·전기차 배터리·날씨)이 위험해집니다.
지금 100% 인 거부 정확도와 환각 0건을 오거부 3건과 맞바꾸는 셈입니다.

**B. 데이터로 푼다 (권장)** — 회귀 위험이 없고 우리 담당입니다.
지금 뽁뽁이는 품목 열몇 개가 섞인 나열형 청크에 파묻혀 있어 짧은 질문과
유사도가 떨어집니다. 3순위 과제인 **`[가이드]_공통_헷갈리는품목_모음.txt`** 를
만들면서 품목별로 블록을 쪼개면, 라벨에 "에어캡(뽁뽁이)" 이 그대로 들어가
검색 표면이 커집니다. q018·q020 을 살린 것과 같은 방법입니다.
